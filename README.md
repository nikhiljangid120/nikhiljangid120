## How I Approach AI Engineering

AI is interesting to me when it becomes part of a **complete software system**, not when it exists as an isolated model call.

```text
                    USER PROBLEM
                         │
                         ▼
                  APPLICATION CONTEXT
                         │
                         ▼
              ┌──────────────────────┐
              │ Retrieval / Tools /  │
              │ Structured Inputs    │
              └──────────┬───────────┘
                         │
                         ▼
                    MODEL / AGENT
                         │
                         ▼
                 VALIDATION / RULES
                         │
                         ▼
                  APPLICATION STATE
                         │
                         ▼
                     FEEDBACK
                         │
                         └──────→ ITERATE
```

The engineering questions I'm learning to answer:

- **Context:** what information should the model receive?
- **Retrieval:** when should search happen, and how should results be ranked?
- **Tools:** when should the model call a tool instead of generating an answer?
- **Reliability:** what happens when a model or provider fails?
- **Validation:** how do we keep generated output from corrupting application state?
- **Evaluation:** how do we measure whether an AI feature is actually useful?
- **Architecture:** where should memory, tools, business logic, and state live?
